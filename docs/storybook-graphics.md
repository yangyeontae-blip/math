# 동화풍 3D 그래픽 검증 — 2026-10-26

기준 버전은 345b399. 저장·보상·문제·음성·서버는 변경하지 않고 마을, 학교, 집과 기존 숲의 렌더링을 개선했다.

## 표현과 성능

- 창틀·처마·목재·기단, 비대칭 수관과 숲별 나무 형태를 적용했다. 작은 자체 생성 질감은 주소 외부에서 내려받지 않는다.
- 잎과 풀은 공유 셰이더로 흔들리며, 반복 풀과 길가 돌은 인스턴스로 그린다. 안개 덮개를 제거하고 캐릭터 접지 그림자는 가벼운 화면에서도 유지한다.
- 가벼운 화면은 풀을 180→60개로 줄이고 물결과 바닥 질감을 생략한다. 지도 전환 시 전용 geometry·instance·물 재질을 해제하며 공유 자원은 유지한다.
- 공유 소스 77개를 웹·앱에 동기화했다. 앱의 가명·오프라인·이용권과 웹의 온라인 기능은 플랫폼별 소스에 유지한다.

## 확인한 범위

- 390×844, 844×390, 768×1024, 1280×900에서 광장·상점·정원·학교·네 계산 숲의 변경 전후 32개 장면씩 확인했다. 자바스크립트·셰이더 오류는 없었다.
- 휴대폰 크기에서 모션을 켜고 8개 장면의 이동 전후를 확인했다. 별도 실제 렌더러 검사로 눈·낙엽·밤 반딧불과 물 파문, 동작 줄이기의 효과 제거를 확인했다.
- 기존 PC·모바일 브라우저 검사 8개가 통과했다. 학교 입장·스킬·수련·재접속, 힌트·오답 재도전·즉시 저장·리포트, 정원 배치 복원과 저장 손상·실패 처리를 포함한다.
- 웹 303개·앱 281개 단위 테스트가 통과했다. 새 검사는 그림자 공유와 높은 포장면 접지, 흔들림 경계, 입자 재순환, 수면의 변환 좌표와 50회 장면 자원 해제를 확인한다.
- 별도 렌더러 검사로 네 계산 숲의 1~10단계 40개와 마을 테마 12개, 방과 학교를 확인했다. 이는 각 장면 생성 검사이며 40회 전체 플레이 완료를 뜻하지 않는다.

## 측정 조건과 제한

Chrome headless, SwiftShader 소프트웨어 렌더링, DPR 1 조건이다. 휴대폰·태블릿 크기는 가벼운 화면, PC는 기본 화면으로 비교했다. 워밍업 뒤 30프레임 간격을 측정하고 느려진 대표 장면은 같은 조건으로 각각 세 번 비교했다. 실제 휴대폰 FPS·발열·배터리 측정은 아니다.

태블릿 곱셈 숲은 초기 중앙값 116.65ms가 나와 가벼운 화면의 큰 바닥 질감을 생략했다. 조정 뒤 세 번 중앙값은 66.6ms이며 기준은 66.7ms였다. 휴대폰 학교는 전후 16.7ms, 휴대폰 광장은 반복 중앙값 50→33.3ms였다. 이 표본을 모든 기기의 성능 향상으로 해석하지 않는다.

태블릿 집·학교의 짧은 순차 측정에서는 20% 초과 저하가 나왔다(집 50→83.3ms, 학교 16.7→66.6ms). 이를 삭제하거나 통과로 바꾸지 않았다. 이후 동일 브라우저에서 기준→변경→기준→변경을 번갈아 열고, 장면 진입 후 2.5초 안정화 및 각 120프레임과 CPU 프로파일로 재확인했다. 학교 중앙값은 기준 66.7/66.7ms, 변경 66.6/66.6ms였다. 집 첫 비교는 33.4→33.3ms였다. 이 통제 비교에서는 20% 초과 저하가 재현되지 않았다. 소프트웨어 렌더링의 실행 부하·표본 길이에 따른 편차가 크므로 실제 태블릿 성능을 보증하지 않으며 출시 후 실기기 확인이 필요하다.

공개 메뉴로 워밍업 2회와 본측정 10회, 총 72개 지도 지점을 순회했다. 살아있는 WebGL context는 1개였고 장면별 buffer·texture 객체 수는 반복 누적되지 않았다. 정원은 buffer 439~442, draw 162~163으로 변동하며 다음 광장에서 동일 기준값으로 돌아왔다. 모든 첫·끝 값의 완전 동일성을 요구한 임시 검사의 엄격한 조건은 정원에서 미충족이므로 무조건 성공으로 표현하지 않는다. 이는 GPU 메모리 바이트 측정이 아니다.

동일 휴대폰 크기·저품질 조건에서 프레임당 draw 호출은 상점 341→351, 광장 249→265, 학교 119→120, 정원 154→162~163이다. 세부 표현 추가로 호출 수는 증가했다.
